# 幫戰覆盤新頁規格

## 1. 目標

- 獨立做一個新的 `html`
- 用來處理：
  - 單場幫戰覆盤
  - 多場累積分析
  - 玩家長期表現
  - 同職業逐人數據表
- 分析邏輯以 [幫戰覆盤分析規則.md](幫戰覆盤分析規則.md) 為準

## 2. 檔案建議

- 新檔名：
  - `battle_review.html`
- 不和 `calculator.html` 混在一起
- 資料儲存獨立，不污染既有配裝資料
- 手機版另做獨立檔：
  - `battle_review_mobile.html`

### 手機版部署資訊

- GitHub Pages repo：
  - `https://github.com/justO-arch/jol-battle-review`
- 手機網址：
  - `https://justo-arch.github.io/jol-battle-review/`
- GitHub Pages 入口檔：
  - `github_pages_mobile/index.html`

### 桌機版與公開唯讀部署資訊

- 桌機個人工具網址：
  - `https://justo-arch.github.io/jol-battle-review/desktop/`
- 桌機公開唯讀網址：
  - `https://justo-arch.github.io/jol-battle-review/desktop/?public=latest`
- 公開手機橫版網址：
  - `https://justo-arch.github.io/jol-battle-review/desktop/?public=latest&view=landscape`
- 桌機入口檔：
  - `github_pages_mobile/desktop/index.html`
- 公開資料檔：
  - `github_pages_mobile/desktop/public-data/latest.json`
- 公開資料檔格式：
  - 直接沿用 `battle_review_export_*.json`
  - 不另外設計第二套 schema
- 公開資料更新流程：
  - 將新的覆盤匯出 JSON 覆蓋到 `github_pages_mobile/desktop/public-data/latest.json`
  - commit 並 push GitHub Pages repo
  - 公開版會在下次載入時讀取最新 `latest.json`
  - 導頁按鈕維持乾淨網址，不主動在頁面網址加 `v`
  - 程式內部讀取 `public-data/latest.json` 時會自動加 `v=Date.now()` 避免資料快取
  - 若剛推完仍看到舊版頁面本體，可手動在網址加 `&v=任意新字串` 避開 GitHub Pages 快取

桌機版目前有兩種模式：

- 個人工具模式：
  - 使用者自行匯入戰報 `CSV`
  - 匯入分工 `CSV`（選配），沒有分工表時加入場次會自動推測分工
  - 資料寫入使用者自己的瀏覽器 `localStorage`
  - 可編輯 metadata、分工、別名與刪除場次
- 公開唯讀模式：
  - 使用 `?public=latest` 讀取 GitHub Pages 上的公開 JSON
  - 不自動寫入訪客 `localStorage`
  - 可查看所有報表與匯出 PDF
  - 禁用 CSV 匯入、加入場次、metadata 編修、分工修改、刪除、JSON 匯入覆蓋
  - 左側匯入流程會隱藏，右側覆盤主區保留完整功能
  - 預設打開 `單場覆盤` 分頁，不顯示 `分工` 分頁，也不還原匯出者自己的分頁與篩選狀態（2026-10-20 起；之前預設打開 `分工`）
  - 頁首狀態列顯示資料匯出時間（換算成台灣時間）與場次範圍；別名合併的輸入列與單場的人工備註欄不顯示
  - 若訪客想基於公開資料繼續工作，需按 `從公開資料建立本機副本`
  - 網址可以指定分頁與場次（2026-10-23）：`&tab=`（單場覆盤、單場對位、重點人物、職業表現、玩家象限、小隊表現、玩家查詢、判讀說明）與 `&battle=<場次 id>`；切換分頁或場次時網址跟著改；「資料」選單的「複製本頁連結」複製目前網址。指定的場次找不到時改用最新一場，公開版看不到的分頁改開單場覆盤。場次參數改的是「切換場次」那一場（單場覆盤、單場對位、重點人物），職業表現等統計分頁照舊預設只勾最新一場

公開手機橫版檢視：

- 使用同一個 `github_pages_mobile/desktop/index.html`，不另開第二套分析邏輯。
- 觸發條件為：
  - `?public=latest&view=landscape`
- 只在符合條件時套用 `body.public-landscape`：
  - 一般桌機個人工具 `/desktop/` 不受影響。
  - 標準公開唯讀 `/desktop/?public=latest` 不吃手機橫版樣式。
- 公開版按鈕導頁規則：
  - `查看公開版` 導向 `/desktop/?public=latest`
  - `手機橫版檢視` 導向 `/desktop/?public=latest&view=landscape`
  - `標準公開版` 會移除 `view=landscape`
  - 上述導頁不再產生新的 `v=Date.now()`，避免分享網址每次不同。
- 手機橫版整體版面：
  - 壓縮 hero 標題區。
  - 分頁列固定為緊湊橫向操作。
  - 直向打開會提示建議改用橫向瀏覽。
- `玩家查詢` 手機橫版規則：
  - 輸入玩家名稱時不即時重算。
  - 按 `搜尋` 或 Enter 後才執行查詢。
  - 六格圖改成橫向滑動卡片。
  - 摘要資訊改成橫向滑動小卡，長文字允許換行並在卡片內捲動。
  - 完整對比表固定欄寬並可橫向滑動，避免 `PR` 欄與判讀欄被截掉。
- `單場對位` 手機橫版規則：
  - 比較表限制在卡片內橫向滑動。
  - 己方與對方名單改為上下堆疊。
  - 玩家指標文字允許換行。
  - `syncMatchupTableWidthToRoster()` 在公開手機橫版下直接跳過，避免 JS 把名單寬度重新撐開。
- `重點人物` 手機公開版規則：
  - 一般重點人物摘要卡允許換行。
  - 鐵衣與素問重點卡在手機橫版下佔滿整列。
  - `化羽 / 淨治療 / 治療 / 承傷 / 重傷` 等長指標強制解除 `nowrap`。
  - `900px` 以下公開唯讀版重點人物改成單欄。

建立本機副本規則：

- 若訪客瀏覽器沒有本機資料，直接用公開資料建立私人副本。
- 若已有本機資料，讓使用者選擇：
  - `覆蓋我的本機資料`
  - `合併到我的本機資料`
  - `取消`
- 第一版合併規則：
  - 只合併 `battles`
  - 保留訪客本機的 `aliasMap`、`settings` 與其他個人設定
  - 先用 `id` 去重
  - 再用 `date + sourceLabel + teamName + opponent` 去重
  - 重複時保留本機資料，公開資料只補不存在的場次

手機端建議使用方式：

- 用 `Safari` 開 GitHub Pages 網址
- 再使用：
  - `批量匯入目前所有資料`
- 匯入檔案需使用：
  - `battle_review_export_*.json`
- 不可直接使用：
  - `jol_backup_*.json`

手機版目前的實務結論：

- 不建議直接在手機上打開本地 `html`
  - 尤其 `iPhone` 的本地檔案預覽模式，常沒有真正網址，`file input` 也容易失效
- 正式使用方式改為：
  - 先部署 GitHub Pages
  - 手機以瀏覽器開網址
  - 再匯入 `battle_review_export_*.json`
- 手機版維持獨立檔：
  - `battle_review_mobile.html`
  - 不直接動桌機版 `battle_review.html`

## 5. 場次管理區

用途：

- 匯入與管理多場戰報

功能：

- 匯入單場 `CSV`
- 設定：
  - 日期
  - 對手
  - 己方名稱
  - 備註
- 顯示已載入場次清單
- 可刪除單場紀錄
- 可編輯場次資訊
- 新增場次（2026-10-21）：日期取自戰報檔名開頭的年月日，手動改過的不蓋掉；和已加入的場次重複時先確認；加入後清空戰報、勝敗、日期與備註（分工表 2026-10-23 起也清空，不沿用到下一場）
- 新增場次精簡（2026-10-23 使用者要求）：步驟 1 選戰報 CSV（必要），選好就自動讀取，不用再按「讀取戰報」；步驟 2 選分工 CSV（選配），選好就讀取，沒有分工表就不用選，加入時依資源、塔傷和擊殺自動推測分工（拿掉「若無分工表請打勾」，以前沒勾會擋下加入），要改分工到「分工」分頁改；步驟 3 看讀取結果後按大按鈕加入。戰報區段、對手、己方名稱與備註收在「其他場次資料」，加入後也能用「編輯場次資訊」修改。取消選檔不跳提示；讀取中加入按鈕先停用
  - 同日第二批：勝敗依雙方總塔傷自動判讀（己方 35 場用這條規則全部判對；同分或沒有對手資料時維持未標記），日期取自檔名，兩者手動改過都不蓋掉，換己方那一段時勝敗跟著換
  - 分工表不沿用到下一場：有選才有，加入後清空；選錯可按「移除這份分工表」
  - 分工表自動略過、不跳提示：格式不對（讀不到 name、group_type）或沒有任何人標團別時，步驟 2 寫出略過原因；對上有團別的人（兩側合計）不到己方人數一半時，加入時略過、改由數據推測（例如別幫或別天的分工表只對上一兩人）。對上一半以上就照分工表，沒對上的人維持未定
  - 沒有分工表（或被略過）時，推測出的團別也直接當分隊（進攻／防守／保鑣），小隊表現就分成這三組
  - 步驟 2 的「沒有分工表，加入時由數據自動推測分工。」用紅字、稍大
- 加入新場次後（2026-10-23 使用者要求）：職業表現、玩家象限、小隊表現的場次清單改成只勾這一場（新加的不一定是日期最新的，例如補登舊場次）；該分頁的己方或對手篩選會擋掉這場時改回全部。重點人物跟著「切換場次」換到這場、只勾這場
- 小隊表現的提醒：「建議只看單場或同一次約戰較有價值，因為不同場的隊員/對手組成很可能大不相同。」（2026-10-23）
- 分工表格式（2026-10-23 放寬）：
  - 第一個同時有「玩家名字」與「團別」的列就是標題列，前面可以有表名等幾行；欄位順序不限，多的欄位忽略，括號裡的說明不算
  - 欄位名稱英文中文都認得：玩家名字（name／玩家名字／玩家／玩家ID／ID／名字／角色名）、團別（group_type／團別／分組／組別／分工）、隊伍（subgroup／隊伍／小隊／分隊）、職業（job／職業）、特殊身分（special_roles／特殊身分／特殊職責）、備註（note／備註）
  - 團別：含「保鑣／保鏢」算保鑣，含「進攻」或以「攻」開頭算進攻，含「防守」或以「守」開頭算防守（英文 attack／defense／bodyguard），其他算未定
  - 特殊身分可用逗號、頓號、分號或斜線分隔；寫「指揮」或 commander 是指揮，lag 是卡頓豁免
  - 逗號或 Tab 分隔；UTF-8 讀不出來時改用 Big5（Excel 在繁中 Windows 存的 CSV）。Big5 存不了的字會變成問號，那幾人對不上
  - 比對只看名字是否和戰報完全相同；職業欄不參與比對
- 下載空白分工表模板（2026-10-23）：新增場次步驟 2 與分工頁各一個按鈕，下載「分工表模板.csv」（UTF-8 BOM，欄位：玩家名字（和遊戲內完全相同）、職業、團別（進攻/防守/保鑣）、隊伍（例如 進攻一隊）、特殊身分（指揮）、備註）。用途是讓別幫把模板和自家分工截圖交給 AI 填好再匯入。新增場次步驟 2 的提醒是紅字、稍大的「可以把分工模板、戰報、自家分工截圖交給chatgpt等AI填好再匯入」
- 分工頁按鈕排法（2026-10-23 使用者要求）：三排，每排是自動轉某團別、旁邊「將選取玩家設為」同一團別（白色按鈕），第三欄依序是一鍵自動分進攻防守、將選取玩家設為未定、重置所有分工（紅色按鈕）；人數統計在最右邊。1240px 以下人數換到下一行，900px 以下每排的自動轉獨占一行、兩個按鈕排在它下面
- 重點人物六角圖的比較對象（2026-10-23 使用者要求，只在重點人物）：拆塔最強和進攻團比，打人最強、擊殺最多和防守+保鑣團比，都不分職業；其他項目照舊和同職業比。用重點人物勾選的場次；玩家本人的數據用他在這些場次的全部分工，若不在那個團別就註明僅供橫向參考。說明寫成紅字的「比較對象固定為…」；其他頁的六角圖和同職業比，說明同樣是紅字的「比較對象固定為同職業」
- 「母體」一律改叫「比較對象」（2026-10-23 使用者要求）：六角圖說明、比較對象中位數圖／平均數圖、玩家查詢的比較表欄位與警告。數據估算的「共同母體」是統計用語，沒有改；手機頁沒有改
- 分工頁「匯入分工表」（2026-10-23）：套用到目前場次。格式不對、沒人標團別或對上不到己方一半時，跳提醒並略過，目前場次的分工不動；可以套用時先確認對上幾人，套用後只改對上的人，不在分工表的人不動

第一版建議：

- 先手動管理場次
- 不做太複雜的批次匯入

## 6. 分工設定區

每場戰報需綁定分工。

每位玩家至少要有：

- `group_type`
  - `attack`
  - `defense`
  - `bodyguard`
  - `unknown`
- `subgroup`
  - 例如：
    - `進攻一隊`
    - `防守三隊`
- `special_role`
  - 可複選或文字標記：
    - `commander`
    - `healer`
    - `burner`
    - `special_task`

第一版建議：

- 以 `分工 CSV` 自動套用為主
- 表格仍保留手動微調能力
- 之後再做分工模板複用

目前桌機版分工頁已補上：

- 分工表最上方直接列出本場 `commander` 名單
- 並加紅字提醒：
  - `分工和指揮名單可修改`

## 7. 單場覆盤區

用途：

- 依現行規則輸出單場檢討結果

區塊內容：

### 7.1 團隊摘要

顯示：

- 總擊敗
- 總助攻
- 總資源
- 總對玩家傷害
- 總對建築傷害
- 總治療
- 總承傷

若有雙方資料，還可顯示：

- 己方 vs 對手差值

### 7.2 第一輪門檻篩選

依最新規則分成大母體主指標。

第一版不再把所有第一輪名單集中堆成一大塊表；單場覆盤上方只顯示：

- 己方整體數據
- 對手整體數據（若同份戰報可取得）

真正需要看的名單，直接以下方三欄為主：

- `優先找幹部覆盤`
- `歡迎找幹部覆盤`
- `系統難以判定`

- `進攻團 DPS（排除素問）`
  - `塔傷後 30%`
- `防守 / 保鑣團 DPS（排除素問）`
  - `人傷後 30%`
  - `擊殺後 30%`
- `進攻團素問`
  - `化羽後 30%`
  - `淨奶量後 30%`
- `防守 / 保鑣團素問`
  - `化羽後 30%`
  - `淨奶量後 30%`
- `進攻團`
  - `重傷前 30%`
- `防守 / 保鑣團`
  - `重傷前 30%`

第二輪再補看次級指標：

- 進攻團 DPS：
  - `人傷`
  - `助攻`
- 防守 / 保鑣團 DPS：
  - `助攻`
- 素問：
  - `治療量`
  - `承受傷害`
- 九靈：
  - `焚骨`
- 鐵衣：
  - 若標記坦位，再看 `承傷 + 重傷`

### 7.3 正式名單

分三欄：

- `優先找幹部覆盤`
- `歡迎找幹部覆盤`
- `系統難以判定`

另外在三欄名單上方，獨立顯示：

- `指揮（commander）`

口徑：

- `commander` 不列入數據評估
- 只獨立列名單
- 固定提示：
  - `不列入數據評估，建議看錄像評估決策狀況。`

每筆至少顯示：

- 名字
- 職業
- 分工

### 7.4 單場對位

桌機版已新增獨立分頁 `單場對位`，放在 `單場覆盤` 旁邊，不再把雙方同職業對位塞回單場覆盤頁裡。

用途：

- 觀察這場雙方同職業、同分組類型的對位差異
- 幫助幹部快速判斷：
  - 是整體職業對位落後
  - 還是某一組 / 某幾位玩家特別落後

目前頁面口徑：

- 主要看同職業對位
- 己方分組使用場次內已保存的 `groupType`
- 對手分組為系統推定，不是原始分工資料
- 對手分組與 `職業表現 -> 分析對手` 共用同一套推測規則：
  - `資源 > 0` 且 `塔傷 < 1000萬` 判為 `防守`（2026-10-22 起；防守順手打塔時，只看塔傷會被算成進攻）
  - 其餘 `塔傷 >= 1萬` 先判為 `進攻`
  - `塔傷 < 1萬` 判為 `防守`
  - 若先判為 `進攻`，但 `塔傷 < 5000萬` 且 `擊殺 > 5`，改判為 `保鑣`
- 單場對位顯示時，`進攻` 與 `保鑣` 合併成 `進攻+保鑣組`，`防守` 獨立成 `防守組`
- 最上方職業配置卡的說明中，「對方分組依資源與塔傷推測」用紅字、比旁邊的說明大一點，提醒對方分組不是真實分工（2026-10-23 使用者要求）
- 這套分組顯示口徑會套用到所有 DPS、`鐵衣`、`素問`
- 舊版 `對手 DPS 擊殺門檻` 已移除
- 對位頁的「上下表中線對齊」目前已定案：
  - 不直接縮上表總寬
  - 改以下方左右名單盒去對上方分隔線
  - 先取上表 `己方平均 / 對方總量` 中間分隔線位置
  - 換算出下方左右白盒的理論左右寬
  - 若視覺上仍偏左，可先對左側理論寬乘一個補正倍率
  - 再把左右寬換成 `flex` 比例，寫回下方左右白盒
  - 這樣可以因應不同職業、不同組別的內容長度差異，不必手動為每張卡設固定比例

## 12. 規則設定區

用途：

- 讓規則可調，但預設仍採現在定案

第一版可調：

- 後段門檻 %
- 高重傷門檻 %

固定先內建：

- 進攻團 DPS 看塔傷
- 防守 / 保鑣團 DPS 看人傷與擊殺
- 素問主看化羽、淨奶量
- 素問次看治療量、承傷
- 重傷分成：
  - `進攻團`
  - `防守 / 保鑣團`
- 九靈補看焚骨
- 潮光補看清泉
- 防守／保鑣潮光（2026-10-23）：人傷、擊殺低不算弱項，改看助攻與清泉是否在防守／保鑣潮光後 `30%`；兩項都弱進歡迎、再加高重傷進優先，一項弱要高重傷才進歡迎；人傷或擊殺達同側 DPS 中位數就排除。詳見 `幫戰覆盤分析規則.md` §10 潮光
- 九靈 / 潮光單場覆盤特殊項（防守／保鑣潮光除外）：
  - 單弱 + 同側同職業特殊項後 `30%`，升到 `歡迎找幹部覆盤`
  - 主責弱 + 高重傷 + 同側同職業特殊項後 `30%`，升到 `優先找幹部覆盤`
  - 特殊項指 `九靈焚骨`、`潮光清泉`
  - 九靈焚骨的「後 `30%`」2026-10-23 起改成比同側九靈第二名少 `40%` 以上（不到 3 人和第一名比）；分工分數的焚骨改成額外加分（有燒 +5，再加焚骨 PR × 0.10，上限 100）
- 潮光清泉保護：
  - `清泉 > 10` 或清泉位於同側同職業前 `30%`
  - 且 `清泉數 > 自身重傷數`
  - 符合時排除於單場覆盤自動名單外
- 鐵衣若為坦位，補看承傷與重傷

## 13. 規則引擎

必須直接依 [幫戰覆盤分析規則.md](幫戰覆盤分析規則.md) 實作。

核心流程：

1. 匯入戰報
2. 匯入分工 CSV
3. 用 `name` 綁定分工
4. 依分工決定主母體與特殊母體
5. 跑第一輪門檻篩選
6. 統計交集
7. 再結合特殊職責做人工判讀輔助

補充規則：

- `素問`
  - 不看塔傷 / 人傷 / 擊殺
  - 主看：
    - 化羽
    - 淨奶量
  - 次看：
    - 治療量
    - 承受傷害
- `淨奶量 = 治療 - 自己承傷`
- `九靈`
  - 額外看焚骨
- `潮光`
  - 額外看清泉
- `九靈 / 潮光`
  - 單弱 + 同側同職業特殊項後 `30%`，進 `歡迎找幹部覆盤`
  - 主責弱 + 高重傷 + 同側同職業特殊項後 `30%`，進 `優先找幹部覆盤`
- `潮光`
  - 若 `清泉 > 10` 或清泉位於同側同職業前 `30%`
  - 且 `清泉數 > 自身重傷數`
  - 不進單場覆盤自動名單
- `重傷`
  - 只當警戒，不會單獨判斷成有問題
  - 並且分開看：
    - `進攻團重傷前 30%`
    - `防守 / 保鑣團重傷前 30%`
- `所有職業 / 所有分工 / 所有人`
  - 若命中任一通用保護規則
  - 直接排除於自動名單之外

    - `系統難以判定`
- 這些都在匯入後依原始資料重新計算

匯入規則（2026-10-21 起；第一版只有覆蓋模式）：

- 選好檔案後先顯示確認視窗，列出本機與檔案的場數、最新日期，以及檔案中有幾場本機沒有
- `只加入缺少的場次`：同 id，或日期、場次標記、己方、對手都相同，就算本機已有；本機原有的場次、分工、別名與門檻不變，也不套用檔案的 `ui_state`
- `整份覆蓋`：用檔案取代本機全部資料
- `匯入前先下載一份目前的資料` 預設勾選，檔名為 `battle_review_export_日期_匯入前備份.json`；本機沒有場次或存檔讀不出來時不顯示
- 本機存檔讀不出來時只能整份覆蓋
- 整份覆蓋成功後：
  - 直接覆蓋本頁 localStorage 狀態
  - 清空目前暫存中的戰報 / 分工草稿
  - 重新渲染頁面
  - 套回 `ui_state`

## 一句話總結

這個新頁的核心不是漂亮的戰報展示，而是：

- 把現在已定的覆盤規則做成可重複執行的工具
- 支援多場累積
- 能看全員、看同職、看個人歷史
- 最後把單場印象，變成長期表現判讀
